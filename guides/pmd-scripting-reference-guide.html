1 · Introduction & the Script Model

PMD Scripting is the lightweight expression language embedded inside a Workday Extend Presentation Model Definition (PMD). Wherever a value in a PMD can be dynamic, you replace the literal with a script expression. The platform evaluates the expression at runtime and substitutes the result into the page.

The <% … %> delimiters

All embedded script lives between <% and %>. Anything outside the delimiters is treated as a literal string. A value can mix literal text and script, or be pure script:

"label": "Welcome"                         // literal text
"label": "<% 'Welcome, ' + worker.firstName %>"  // pure script
"label": "Hi <% worker.firstName %>!"      // mixed literal + script

What a script returns

A PMD script is a sequence of zero or more statements. By default it returns the value of the last expression it evaluated. An explicit return returns its operand (or null if nothing follows). Statements may optionally be terminated with a semicolon ;.

<% 
  var first = worker.firstName;
  var last  = worker.lastName;
  first + ' ' + last        // last expression is returned
%>

Where script appears

Script is used in three broad places: inline value bindings on widget properties (value, label, visible, …), event handlers (onChange, onClick, onRowSelect), and a page-level script block that runs at page load to define functions and initialize state. Reusable logic is factored into script modules (.script files), covered in Part 10.

2 · Lexical Structure

Comments

Single-line comments begin with //. Multi-line comments are wrapped in /* … */. Comments are removed before evaluation and never affect output.

// a single-line comment
/* a
   multi-line comment */

Identifiers & variable names

An identifier must start with a letter (a-z A-Z), an underscore _, or a dollar sign $. Subsequent characters may also include digits 0-9. Names are case-sensitive — var1 and Var1 are different variables.

ValidInvalid
var1, _a99, $19v, !a99, 1$

Reserved keywords

These words are reserved and cannot be used as variable or property names:

andbreakcatchconstcontinuedodivelseeqfalsefinallyforfunctiongegtifinstanceofltleletmodnenewnotnullorreturnthrowtruetrytypeofvarwhile

Dot vs. bracket notation

Use dot notation to access object properties: worker.firstName. When a property name is a reserved keyword or contains a character the parser would read as an operator (such as a hyphen, which it reads as subtraction), switch to bracket notation:

event.for.id        // ERROR: 'for' is reserved
event['for'].id     // correct

someVariable.a-b    // parsed as subtraction (a minus b)
someVariable['a-b'] // correct: reads the 'a-b' property

3 · Variables & Scope

Three keywords declare local variables. They differ by scope and mutability. The best-practice order is const → let → var — reach for the tightest scope that works.

const — block-scoped, immutable

Defines a block-level variable whose value cannot be reassigned. A block is logic enclosed in { }. Reassignment raises an error, and the variable is not visible outside its block.

const tenant = 'gms';
tenant = 'amu';   // ERROR: cannot reassign a const

if (condition) {
  const tax = 0.2;
}
console.info(tax); // ERROR: 'tax' is out of scope here

let — block-scoped, reassignable

Block-scoped like const, but its value may change within the block. Use it when the value genuinely changes but you want to keep the scope small.

let total = 0;
total = total + amount;   // allowed

var — script-scoped

Has the entire script as its scope and takes precedence over context variables during name resolution. It is the widest scope; prefer const/let unless you need script-wide reach.

var x;                 // basic declaration
var theAnswer = 42;    // declaration with assignment
// var x.y;            // INVALID

4 · Data Types & Literals

Strings

Single or double quotes create a plain string literal.

var a = 'gms';
var b = "amu";

Template strings (backticks & {{ }})

Enclose a string in backticks to enable variable interpolation with the double-brace {{var}} syntax and to write multi-line text. This is a Workday-specific detail: interpolation is {{name}}, not ${name}.

var name = 'Logan McNeil';
var greeting = `Hi, {{name}}`;            // "Hi, Logan McNeil"

var message = `
  Hi, {{name}}
  How are you doing?
`;                                         // multi-line

Numbers, booleans, null

Numbers are unquoted (42, 0.2). Booleans are true / false. The absence of a value is null.

Lists, maps, and sets

PMD supports three object collections. They are covered in depth in Parts 9 and 15.

TypeLiteralNotes
List[1, 2, 3]Ordered; index with arr[0].
Map{'a': 1} · empty: {:}Unordered key–value pairs; the empty map literal is {:}, not {}.
Set{1, 2, 3}Unordered, unique elements.

Map key trap: in {a: 'value'} the key a is treated as a variable. If a is not declared you get an error. Quote the key — {'a': 'value'} — to use a literal string key.

Ternary, null-coalescing & optional chaining

The ternary ?: chooses between two values. The condition evaluates to false when it refers to an undefined variable or null. Null-coalescing ?? returns the left operand if it is non-null, otherwise the right. Optional chaining ?. safely reads a nested property without erroring when an intermediate is null.

!empty worker.middleName ? worker.middleName : ''   // ternary guard
name ?? 'Unknown'                                   // fallback when null
map.foo.bar123?.upperCase()                         // no error if bar123 is null

Ranges

The inclusive to and exclusive until operators build numeric ranges (step 1), most often to drive a for loop.

for (var i : 1 to 50) { list.add(i); }   // 1 through 50 inclusive

6 · Statements & Control Flow

Statements & blocks

A statement may be an empty statement (;), a block, an assignment, or an expression. A block is multiple statements inside curly braces { }. An assignment sets a variable: myVar = 'a value'.

Conditionals

if (empty selection.value) {
  message.value = 'Pick a row first';
} else if (selection.value[0] == 'A') {
  message.value = 'Option A';
} else {
  message.value = 'Other';
}

Loops — for

Two forms are supported: a C-style counter loop and a range loop.

// counter form
for (let i = 0; i < items.size(); i++) {
  total = total + items[i].amount;
}

// range form (inclusive)
for (var i : 1 to 50) {
  increments.add({ 'id': i, 'descriptor': i });
}

Loops — while

while (isWeekend(date) || isHoliday(date, holidays)) {
  date = date:add(date, 'DAY', 1);
}
// use break to exit early

7 · Functions & Closures

Defining & calling functions

Define a function and assign it to a variable; call it with the standard convention. The body returns its last expression by default.

var add = function(x, y) { x + y };
add(17, 25);    // 42

Closures (arrow functions)

An anonymous function uses the arrow form (x) => { … }. Many collection functions accept a closure.

var target = someEndpoint.data.find(item => { item.id == id });
workers.data.filter(w => { w.isManager == true });
workers.data.map(w => { { 'name': w.descriptor } });

The closure mutation rule

Inside a closure you cannot reassign a variable declared outside it, but you can mutate a collection it captures. Use a for loop when you must mutate a counter.

const list = [];
items.forEach(item => { list.add(item); });   // works (mutating a list)

let n = 0;
items.forEach(item => { n++; });               // does NOT work (reassigning)

for (let i = 0; i < items.size(); i++) { n++; } // works (not a closure)

8 · Built-in Functions: empty & size

empty

empty(arg) returns true when the argument is null, an empty string, a zero-length array, a zero-size collection, an empty map, or an object whose isEmpty() method returns true. Otherwise it returns false. The !empty(…) form is the dominant defensive idiom in production apps.

if (!empty selection.value) {
  var w = getWorkerById.invoke({ 'id': selection.value[0] });
}
panel.visible = !empty(results.data);

size

size(arg) returns 0 for null, otherwise the length of a string or array, or the size of a collection or map.

size('Hello');     // 5
size([1, 2, 3]);   // 3
size(null);        // 0

9 · Working with Collections

Lists, maps, and sets each expose a rich set of functions (the complete catalog is in Part 15). The chainable list transforms are the heart of most PMD data work.

Chaining list transforms

workers.data
  .filter(w => { w.isManager == true })          // keep managers
  .map(w => { { 'name': w.descriptor,            // reshape each row
               'title': w.businessTitle } })
  .distinct();                                   // drop duplicates

Building a query string from a map

var params = {:};                               // empty MAP literal
if (!empty(status.value)) { params.status = status.value[0]; }
if (!empty(type.value))   { params.type   = type.value[0]; }

var pairs = [];
params.forEach((key, value) => { pairs.add(key + '=' + value); });
var qs = pairs.join('&');                        // "status=OPEN&type=TRAVEL"

Flattening nested data

var rows = report.Report_Entry.map(entry => {
  entry.Lines.map(line => {
    line.add('Location', entry.Location_Name);
    return line;
  });
});
rows = list:flatten(rows);

10 · Script Modules

A script module is a .script file that defines reusable logic once and exports it to any PMD that includes it. Maximum file size is 100 KB — chunk larger logic across modules.

The export map

The last statement of a module must return a map that exports its public properties. Exported properties are unmodifiable and must be stateless — always export functions, never values that can change.

var getDaysBetween = function(date1, date2) { /* ... */ };
var getMonth = function(date) { return date:extractValue('MONTH', date); };

/* Export — last statement, returns a map */
{
  "daysBetween": getDaysBetween,
  "getMonth": getMonth
}

Stateless rule: a captured value such as a random UUID is not stateless. Export a function that produces it instead of the captured value.

Loading modules — include

A PMD loads modules through the include array. Files must live in presentation/scripts. When a module loads it runs each top-level statement, loads function declarations into memory, exports the returned map, and provides its name as a binding variable.

"include": [
  "dateCalculations.script",
  "workerDetail.script"
]

Invoking exports

Invoke an exported property as <module>.<property>(<args>).

<% var days = dateCalculations.daysBetween(startDate.value, endDate.value); %>

Predefined-variable rule

Predefined app variables (such as userInfo) are available in PMDs but not inside script modules. A PMD may pass them in as parameters, but the module's function must use a different parameter name.

11 · Endpoints & Data Binding

Endpoints are declared in the PMD's endPoints array and exposed to script by name. Each exposes .data (the payload) and .invoke(<map>).

Declaration

"endPoints": [
  { "name": "workers", "baseUrlType": "workday-common",
    "url": "/workers", "authType": "sso" },
  { "name": "getWorkerById", "baseUrlType": "workday-common",
    "url": "<% '/workers/' + id %>", "authType": "sso",
    "deferred": true }
]

Invoking & deferred

An eager endpoint resolves on page load; a deferred: true endpoint stays idle until your script calls .invoke(…). Pass URL params or a body as a map.

var w = getWorkerById.invoke({ 'id': selection.value[0] });
descriptor.value = w.descriptor;

// pass a pre-built query string
var data = expenses.invoke({ 'params': 'status=OPEN&type=TRAVEL' });
dataGrid.setRows(data.data);

12 · Widgets & Methods

Script reads and writes widget properties by the widget's id.

Value, visibility, enablement

descriptor.value = workerData.descriptor;   // set a field value
workerDetailSection.visible = true;          // show / hide
field.enabled = false;                        // toggle editability

Grids

setRows replaces a grid's data; rows reads/writes the backing list; selectedRows is the user's selection. Reach a cell via childrenMap.

dataGrid.setRows(filteredList);

var id = reqGrid.selectedRows[0].childrenMap.idColumn.value;
reqGrid.selectedRows[0].childrenMap.totalColumn.value = qty * unitCost;

var names = grid.selectedRows.map(row => { row.childrenMap.name.value });

16 · Patterns & Best Practices

Null-safe display

"value": "<% !empty getOpportunity.name ? getOpportunity.name : '' %>"

Reset a page region

var reset = function() {
  searchTerm.value = '';
  resultsGrid.setRows([]);
  detailSection.visible = false;
};

Conditional parameter assembly

var params = {:};
if (!empty(from.value)) { params.fromDate = date:format(from.value, 'yyyy-MM-dd'); }
if (!empty(to.value))   { params.toDate   = date:format(to.value, 'yyyy-MM-dd'); }

Guidelines

  • Prefer const, then let, then var.
  • Keep exported module properties stateless — export functions, not mutable values.
  • Guard every external value with empty/!empty before using it.
  • Use bracket notation for keyword or hyphenated property names.
  • Reuse logic through script modules instead of copying inline scripts between pages.
  • Encode user-supplied values with string:urlEncode before placing them in a URL.
  • Coerce query-param strings with number:convertStringToInt before arithmetic.

17 · Limits & Common Errors

Limits

  • A single .script file is capped at 100 KB.
  • Exported module variables must be static/stateless.
  • Predefined app variables are unavailable inside script modules (pass them as parameters).
