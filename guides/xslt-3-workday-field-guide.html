§1XSLT 3.0 in the Workday world

Workday hands you XML at almost every integration boundary, and XSLT is the in-platform tool for reshaping it.

BoundaryWhat you get / produceTypical XSLT job
RaaS outboundReport_Data XML in urn:com.workday.report/…Flatten to CSV / fixed-width / JSON / a partner schema
EIB outboundA report or WWS responseA Custom Transformation (XSLT Attachment) on the Transform step
Studio / OrchestrateAny message in the pipeXSLT step (Saxon factory) between routes
WWS inboundYou must build a *_RequestBoomerang: RaaS row → XSLT → Put_Worker / Change_*
!
Version reality: Workday's documented Studio best practice is still XSLT 2.0 with the Saxon factory; 3.0 + streaming is taught mainly for high-volume EIB cases. Write 3.0 freely for EIB/RaaS transforms; when targeting a Studio XSLT step, confirm the configured version. Anything that doesn't use streaming/maps/JSON (e.g. the boomerang §3.12) is valid 2.0 and drops straight in.
E
Saxon-HE vs EE: maps, JSON, grouping, try/catch and TVTs are all core 3.0 and run on free Saxon-HE. Only streaming needs Saxon-EE — and a streamable stylesheet produces identical output on HE (it just buffers). So you can develop and test everything on HE, as this guide does.

The #1 RaaS gotcha: the xmlns:wd URI in your stylesheet must match the report's WWS namespace exactly (urn:com.workday.report/<Report_Name>). A mismatch produces empty output with no error — templates simply never match. Best practice: override the report namespace to a value you control.

§3Core features

Each feature: concept → sample stylesheet → real output → why it matters in Workday.

3.1

Text Value Templates

expand-text TVT

Set expand-text="yes" and {…} inside text is evaluated as XPath — replacing a wall of <xsl:value-of> with inline interpolation. Escape a literal brace by doubling it: {{.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    expand-text="yes" exclude-result-prefixes="xs wd">
  <xsl:output method="text" encoding="UTF-8"/>
  <xsl:template match="/wd:Report_Data">
    <xsl:for-each select="wd:Report_Entry">{wd:Legal_First_Name} {wd:Legal_Last_Name} earns {format-number(wd:Annual_Salary,'#,##0')} {wd:Annual_Salary/@wd:Currency}&#xA;</xsl:for-each>
  </xsl:template>
</xsl:stylesheet>
OUTPUT · TEXT ✓ verified
Logan McNeil earns 185,000 USD
John Davis earns 96,000 USD
Oliver Reynolds earns 72,000 GBP
W
In Workday: Building delimited / fixed-format payroll lines is far cleaner with TVTs. Watch the {{ }} escaping rule whenever your output itself contains braces.
3.2

Functions & sequence types

xsl:function types

xsl:function with a namespaced name, typed xsl:params, an as return type, and xsl:sequence to return a value. The right home for business rules — banding, code mapping, formatting.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    xmlns:f="urn:local:fn" expand-text="yes" exclude-result-prefixes="xs wd f">
  <xsl:output method="text" encoding="UTF-8"/>
  <xsl:function name="f:band" as="xs:string">
    <xsl:param name="salary" as="xs:decimal"/>
    <xsl:sequence select="if ($salary ge 150000) then 'A'
                          else if ($salary ge 90000) then 'B'
                          else 'C'"/>
  </xsl:function>
  <xsl:template match="/wd:Report_Data">
    <xsl:for-each select="wd:Report_Entry">{wd:Employee_ID}: band {f:band(xs:decimal(wd:Annual_Salary))}&#xA;</xsl:for-each>
  </xsl:template>
</xsl:stylesheet>
OUTPUT · TEXT ✓ verified
21001: band A
21505: band B
21002: band C
W
In Workday: Centralize mapping logic (pay components, location crosswalks, eligibility) in functions instead of copy-pasted choose blocks. The as types catch bad data early.
3.3

Maps & arrays

map aggregation

First-class maps (map{ k: v }) and arrays (array{}). Build a map from grouped data and you get an O(1) lookup table. Key functions: map:put, map:get/$m(k), map:keys, map:contains, map:size.

!
Saxon strict-typing: declaring as="map(xs:string, xs:decimal)" can throw XTTE0570. Either cast every value and the sum, or use as="map(*)" as shown.
INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:map="http://www.w3.org/2005/xpath-functions/map"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    expand-text="yes" exclude-result-prefixes="xs map wd">
  <xsl:output method="text" encoding="UTF-8"/>
  <xsl:template match="/wd:Report_Data">
    <!-- Build a map: company name -> total salary -->
    <xsl:variable name="byCompany" as="map(*)">
      <xsl:map>
        <xsl:for-each-group select="wd:Report_Entry" group-by="wd:Company">
          <xsl:map-entry key="current-grouping-key()"
                         select="sum(current-group()/xs:decimal(wd:Annual_Salary))"/>
        </xsl:for-each-group>
      </xsl:map>
    </xsl:variable>
    <xsl:text>Companies in map: {map:size($byCompany)}&#xA;</xsl:text>
    <xsl:for-each select="map:keys($byCompany)">{.} = {format-number($byCompany(.),'#,##0.00')}&#xA;</xsl:for-each>
  </xsl:template>
</xsl:stylesheet>
OUTPUT · TEXT ✓ verified
Companies in map: 2
Global Modern Services, Inc. (USA) = 281,000.00
Global Modern Services Ltd (UK) = 72,000.00
W
In Workday: Two big uses: load a crosswalk into a map once then look up per row; or accumulate subtotals while streaming (the map becomes the running state of an xsl:iterate).
3.4

Grouping

for-each-group sort

The workhorse for “group by X, do something per group.” Inside a group: current-grouping-key() is the key, current-group() the members. Modes: group-by, group-adjacent, group-starting-with. Nest them for multi-level grouping.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    expand-text="yes" exclude-result-prefixes="xs wd">
  <xsl:output method="xml" indent="yes" encoding="UTF-8"/>
  <xsl:template match="/wd:Report_Data">
    <Companies>
      <xsl:for-each-group select="wd:Report_Entry" group-by="wd:Company">
        <xsl:sort select="current-grouping-key()"/>
        <Company name="{current-grouping-key()}" headcount="{count(current-group())}">
          <xsl:for-each select="current-group()">
            <xsl:sort select="xs:decimal(wd:Annual_Salary)" order="descending"/>
            <Worker id="{wd:Employee_ID}">{wd:Legal_First_Name} {wd:Legal_Last_Name}</Worker>
          </xsl:for-each>
        </Company>
      </xsl:for-each-group>
    </Companies>
  </xsl:template>
</xsl:stylesheet>
OUTPUT · XML ✓ verified
<?xml version="1.0" encoding="UTF-8"?>
<Companies>
   <Company name="Global Modern Services Ltd (UK)" headcount="1">
      <Worker id="21002">Oliver Reynolds</Worker>
   </Company>
   <Company name="Global Modern Services, Inc. (USA)" headcount="2">
      <Worker id="21001">Logan McNeil</Worker>
      <Worker id="21505">John Davis</Worker>
   </Company>
</Companies>
W
In Workday: Everywhere in real integrations. The INT067 Belgium time transform nests for-each-group by date then by calculation tag, summing per group — the canonical Workday time/payroll roll-up.
3.5

Native JSON output

xml-to-json Saxon-HE

Build the W3C JSON-in-XML vocabulary (xf:map, xf:array, xf:string, xf:number, xf:boolean, xf:null) then serialize with xml-to-json(). No external library, and it runs on Saxon-HE.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<!--
  ============================================================================
  03_report-to-json.xsl
  ============================================================================
  Purpose : Emit JSON directly from a Workday RaaS document using XSLT 3.0's
            native xml-to-json(). Useful for REST endpoints / iPaaS targets
            that want JSON instead of CSV or XML. No external library needed.
  Engine  : Saxon-HE 9.8+ or Saxon-EE (xml-to-json is a 3.0 core feature and
            does NOT require EE). Not declared streamable: building the
            intermediate map tree is an in-memory operation.
  Note    : We construct the W3C JSON-XML vocabulary (xf:map / xf:array /
            xf:string / xf:number) and let xml-to-json() serialize it.
  ============================================================================
-->
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:xf="http://www.w3.org/2005/xpath-functions"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    exclude-result-prefixes="xs xf wd">

    <xsl:output method="text" encoding="UTF-8"/>

    <xsl:template match="/wd:Report_Data">
        <xsl:variable name="json-xml">
            <xf:array key="workers">
                <xsl:for-each select="wd:Report_Entry">
                    <xf:map>
                        <xf:string  key="employeeId"><xsl:value-of select="wd:Employee_ID"/></xf:string>
                        <xf:string  key="firstName"><xsl:value-of select="wd:Legal_First_Name"/></xf:string>
                        <xf:string  key="lastName"><xsl:value-of select="wd:Legal_Last_Name"/></xf:string>
                        <xf:string  key="hireDate"><xsl:value-of select="wd:Hire_Date"/></xf:string>
                        <xf:string  key="company"><xsl:value-of select="wd:Company"/></xf:string>
                        <xf:string  key="costCenter"><xsl:value-of select="wd:Cost_Center"/></xf:string>
                        <xf:number  key="annualSalary"><xsl:value-of select="number(wd:Annual_Salary)"/></xf:number>
                        <xf:string  key="currency"><xsl:value-of select="wd:Annual_Salary/@wd:Currency"/></xf:string>
                        <xf:array key="dependents">
                            <xsl:for-each select="wd:Dependent">
                                <xf:map>
                                    <xf:string key="type"><xsl:value-of select="@wd:Type"/></xf:string>
                                    <xf:string key="name"><xsl:value-of select="wd:Dependent_Name"/></xf:string>
                                </xf:map>
                            </xsl:for-each>
                        </xf:array>
                    </xf:map>
                </xsl:for-each>
            </xf:array>
        </xsl:variable>

        <!-- serialize the JSON-XML vocabulary to a JSON string -->
        <xsl:value-of select="xml-to-json($json-xml, map { 'indent' : true() })"/>
    </xsl:template>

</xsl:stylesheet>

3.6

Native JSON input

parse-json ? lookup

json-to-xml() turns JSON into the JSON-XML vocabulary you can run XPath over; parse-json() turns it into native maps/arrays you navigate with the lookup operator ? ($m?key, $arr?* for “all members”).

INPUT · JSON
{ "workers": [
    { "employeeId": "21001", "name": "Logan McNeil", "salary": 185000, "active": true },
    { "employeeId": "21505", "name": "John Davis",  "salary": 96000,  "active": false }
] }
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    expand-text="yes" exclude-result-prefixes="xs">
  <xsl:output method="xml" indent="yes" encoding="UTF-8"/>
  <!-- path to the JSON file, supplied at launch -->
  <xsl:param name="json-uri" as="xs:string" select="'sample-data/workers.json'"/>
  <xsl:template name="xsl:initial-template" match="/">
    <xsl:variable name="data" select="parse-json(unparsed-text($json-uri))"/>
    <Workers>
      <xsl:for-each select="$data?workers?*">
        <Worker id="{?employeeId}" active="{?active}">
          <Name>{?name}</Name>
          <Salary>{?salary}</Salary>
        </Worker>
      </xsl:for-each>
    </Workers>
  </xsl:template>
</xsl:stylesheet>
OUTPUT · XML ✓ verified

3.7

Streaming I — snapshot pattern

streamable copy-of

Add <xsl:mode streamable="yes"/> and Saxon-EE reads the source forward-only. The rule that keeps you streamable: never look back at a sibling. Stream the outer loop and snapshot one entry with copy-of(.) into a tiny in-memory tree, then read fields from the copy.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<!--
  ============================================================================
  01_report-to-csv.streamable.xsl
  ============================================================================
  Purpose : Outbound EIB / Studio transform. Converts a Workday RaaS
            Report_Data document into a header-row + double-quoted CSV.
  Engine  : Saxon-EE (required for streamable="yes"). Saxon-HE will run it
            non-streamed if you remove the xsl:mode streamable attribute.
  Pattern : Forward-only streaming. We never look back at a sibling entry.
            Each Report_Entry is snapshotted with copy-of() into a tiny
            in-memory tree, then fields are pulled from that snapshot. This
            is the canonical Workday high-volume pattern: stream the outer
            loop, buffer one entry at a time.
  ============================================================================
-->
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    exclude-result-prefixes="xs wd">

    <!-- text output: no XML wrapper, just the CSV bytes -->
    <xsl:output method="text" encoding="UTF-8"/>

    <!-- streamable mode: the processor reads the source forward-only -->
    <xsl:mode streamable="yes" on-no-match="shallow-skip"/>

    <!-- field/record separators centralised so the file is easy to retarget -->
    <xsl:param name="delimiter"   as="xs:string" select="','"/>
    <xsl:param name="quote"       as="xs:string" select="'&quot;'"/>
    <xsl:param name="newline"     as="xs:string" select="'&#xA;'"/>
    <xsl:param name="emit-header" as="xs:boolean" select="true()"/>

    <!--
      Reusable CSV-cell function: wraps a value in quotes and doubles any
      embedded quote (RFC 4180). Pure function, fully streamable.
    -->
    <xsl:function name="wd:csv" as="xs:string">
        <xsl:param name="v" as="xs:string?"/>
        <xsl:sequence select="concat($quote,
                                      replace(string($v), $quote, concat($quote,$quote)),
                                      $quote)"/>
    </xsl:function>

    <!-- entry point: matches the streamed root, prints header, streams rows -->
    <xsl:template match="wd:Report_Data">
        <xsl:if test="$emit-header">
            <xsl:value-of select="string-join(
                ('Employee_ID','First_Name','Last_Name','Hire_Date',
                 'Company','Cost_Center','Annual_Salary','Currency','Dependent_Count'),
                $delimiter)"/>
            <xsl:value-of select="$newline"/>
        </xsl:if>
        <xsl:apply-templates select="wd:Report_Entry"/>
    </xsl:template>

    <!--
      Snapshot each entry, then hand the in-memory copy to a normal
      (non-streamed) template. copy-of() is the streaming-safe boundary.
    -->
    <xsl:template match="wd:Report_Entry">
        <xsl:apply-templates select="copy-of(.)" mode="in-memory"/>
    </xsl:template>

    <xsl:mode name="in-memory" streamable="no"/>

    <xsl:template match="wd:Report_Entry" mode="in-memory">
        <xsl:value-of select="string-join((
            wd:csv(wd:Employee_ID),
            wd:csv(wd:Legal_First_Name),
            wd:csv(wd:Legal_Last_Name),
            wd:csv(wd:Hire_Date),
            wd:csv(wd:Company),
            wd:csv(wd:Cost_Center),
            wd:csv(wd:Annual_Salary),
            wd:csv(wd:Annual_Salary/@wd:Currency),
            wd:csv(string(count(wd:Dependent)))
        ), $delimiter)"/>
        <xsl:value-of select="$newline"/>
    </xsl:template>

</xsl:stylesheet>
OUTPUT · CSV ✓ verified
Employee_ID,First_Name,Last_Name,Hire_Date,Company,Cost_Center,Annual_Salary,Currency,Dependent_Count
"21001","Logan","McNeil","2000-01-01","Global Modern Services, Inc. (USA)","40100","185000.00","USD","2"
"21505","John","Davis","2018-05-14","Global Modern Services, Inc. (USA)","21100","96000.00","USD","0"
"21002","Oliver","Reynolds","2021-09-20","Global Modern Services Ltd (UK)","30000","72000.00","GBP","1"
W
In Workday: The pattern for high-volume outbound (full-population payroll, time, GL) that won't fit in memory. Develop on HE (buffers, identical output); deploy on EE so it actually streams.
3.8

Streaming II — xsl:iterate

xsl:iterate running state

xsl:for-each can't carry state across a streamed pass; xsl:iterate can. Declare xsl:params as running state, update them in xsl:next-iteration, emit a trailer in xsl:on-completion. State must be grounded — snapshot with copy-of().

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    expand-text="yes" exclude-result-prefixes="xs wd">
  <xsl:output method="text" encoding="UTF-8"/>
  <xsl:mode streamable="yes" on-no-match="shallow-skip"/>
  <xsl:template match="wd:Report_Data">
    <xsl:text>Employee_ID,Annual_Salary&#xA;</xsl:text>
    <xsl:iterate select="wd:Report_Entry">
      <xsl:param name="running" as="xs:decimal" select="0"/>
      <xsl:on-completion>
        <xsl:text>TOTAL,{format-number($running,'#,##0.00')}&#xA;</xsl:text>
      </xsl:on-completion>
      <xsl:variable name="e" select="copy-of(.)"/>
      <xsl:text>{$e/wd:Employee_ID},{$e/wd:Annual_Salary}&#xA;</xsl:text>
      <xsl:next-iteration>
        <xsl:with-param name="running" select="$running + xs:decimal($e/wd:Annual_Salary)"/>
      </xsl:next-iteration>
    </xsl:iterate>
  </xsl:template>
</xsl:stylesheet>

21002,72000.00

In Workday: Control totals and trailer records (counts, hash totals, sum-of-amounts) are required by most payroll vendors. xsl:iterate computes them in a single streamed pass — no second read.
3.9

Streaming III — accumulators

xsl:accumulator

An xsl:accumulator updates as the processor walks the document, readable anywhere via accumulator-before/after('name'). It decouples “compute a total” from “where you emit it,” and it streams.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    expand-text="yes" exclude-result-prefixes="xs wd">
  <xsl:output method="xml" indent="yes" encoding="UTF-8"/>
  <xsl:mode streamable="yes" use-accumulators="#all" on-no-match="shallow-skip"/>
  <xsl:accumulator name="rows" as="xs:integer" initial-value="0" streamable="yes">
    <xsl:accumulator-rule match="wd:Report_Entry" select="$value + 1"/>
  </xsl:accumulator>
  <xsl:accumulator name="paySum" as="xs:decimal" initial-value="0" streamable="yes">
    <xsl:accumulator-rule match="wd:Annual_Salary" select="$value + xs:decimal(.)"/>
  </xsl:accumulator>
  <xsl:template match="wd:Report_Data">
    <Summary>
      <xsl:apply-templates select="wd:Report_Entry"/>
      <Rows>{accumulator-after('rows')}</Rows>
      <TotalPay>{format-number(accumulator-after('paySum'),'#,##0.00')}</TotalPay>
    </Summary>
  </xsl:template>
  <xsl:template match="wd:Report_Entry"/>
</xsl:stylesheet>
OUTPUT · XML ✓ verified
<?xml version="1.0" encoding="UTF-8"?>
<Summary>
   <Rows>3</Rows>
   <TotalPay>353,000.00</TotalPay>
</Summary>
W
In Workday: Your SSK*_CountRecords.xsl utilities are exactly this — a streamable record-count accumulator with rule match="/*/*". Use for header/trailer counts and totals without threading state manually.
3.10

Error handling — try / catch

xsl:try resilience

Wrap a risky expression so a failure produces a fallback instead of aborting. The element form <xsl:try><xsl:catch/></xsl:try> works on Saxon-HE; the inline XPath try{…}catch{…} is EE-only. Use the element form for portability.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:wd="urn:com.workday.report/INHCM0001-Outbound"
    expand-text="yes" exclude-result-prefixes="xs wd">
  <xsl:output method="text" encoding="UTF-8"/>
  <xsl:template match="/wd:Report_Data">
    <xsl:for-each select="wd:Report_Entry">
      <xsl:variable name="hire" as="xs:string">
        <xsl:try select="string(xs:date(wd:Hire_Date))">
          <xsl:catch select="concat('INVALID(', wd:Hire_Date, ')')"/>
        </xsl:try>
      </xsl:variable>
      <xsl:text>{wd:Employee_ID}: {$hire}&#xA;</xsl:text>
    </xsl:for-each>
  </xsl:template>
</xsl:stylesheet>
OUTPUT · TEXT ✓ verified
21001: 2000-01-01
21505: 2018-05-14
21002: 2021-09-20
W
In Workday: Source data is never clean — blank dates, “N/A” in numeric fields. xsl:try lets one bad row degrade gracefully (flag, default, route to exceptions) instead of failing the whole run.

analyze-string matches

matches() tests, replace() substitutes, tokenize() splits, and xsl:analyze-string gives structured access via xsl:matching-substring / xsl:non-matching-substring and regex-group(n).

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0

3.12

The boomerang write-back

WWS inbound

Inbound integrations require you to construct a Workday Web Service request. The boomerang reads a RaaS row and emits a *_Request in the operation's bsvc namespace. Uses no streaming or 3.0-only functions, so it's valid under XSLT 2.0 too.

INPUT · RaaS XML
— uses sample-data/report.xml (see §2) —
STYLESHEET · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<!--

  04_raas-to-wws-request.xsl   (the "boomerang" pattern)

  Purpose : Transform a RaaS report row into a Workday Web Service (WWS)
            inbound request so data can be written back into Workday. This is
            the transform half of a boomerang integration

            the Workday Web Services Directory, and the RaaS namespace MUST
            match the report's WWS namespace (best practice: override the

§5–6Wiring into Workday & gotchas

The practical checklist, then the traps that cost the most time.

  1. Namespace match first. Override the RaaS report namespace and copy it verbatim into xmlns:wd. Mismatch = silent empty output.
  2. EIB outbound: Transform step → Custom Transformation → upload the .xsl as an XSLT Attachment; set the step to 3.0 for streaming.
  3. Studio: XSLT step with the Saxon factory — confirm the configured version (many shops standardize on 2.0).
  4. Inbound / boomerang: verify bsvc namespace + version against the Web Services Directory; feed the request to a step that calls the API.
  5. Parameters: surface API version, delimiters, effective dates as xsl:param with defaults.
  6. Test on Saxon-HE locally — identical output to the cloud except for streaming behavior, which only changes memory use.

Gotcha cheat-sheet

Empty output, no error
Namespace mismatch — check xmlns:wd against the report's WWS namespace (§2). The single most common failure.
XTTE0570 building a typed map
Use as="map(*)", or cast both the value and the sum() (§3.3).
“try/catch not allowed in XPath”
You used inline try{}catch{} on Saxon-HE; switch to the <xsl:try> element form (§3.10).
“not streamable” errors
You looked back at a sibling or read a node twice. Snapshot with copy-of(.) and process the copy in a non-streamed mode (§3.7).
Literal brace parses wrong
With expand-text="yes", escape literal braces as {{ }} (matters in regex and hand-emitted JSON).
JSON numbers quoted as strings
Use xf:number / xf:boolean, not xf:string (§3.5).
Trailer total always 0 in a stream
xsl:for-each can't carry state; use xsl:iterate + xsl:next-iteration or an accumulator (§3.8–3.9).

<xsl:stylesheet version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
  xmlns:xs="http://www.w3.org/2001/XMLSchema"
  xmlns:map="http://www.w3.org/2005/xpath-functions/map"
  xmlns:wd="urn:com.workday.report/INHCM0001-Outbound" expand-text="yes" exclude-result-prefixes="xs map wd">

  <xsl:template match="wd:Report_Data">
    <xsl:iterate select="wd:Report_Entry">
      <xsl:param name="subtotals" as="map(*)" select="map{}"/>
      <xsl:on-completion>
        <xsl:for-each select="sort(map:keys($subtotals))">{.}: {format-number($subtotals(.),'#,##0.00')}&#xA;</xsl:for-each>
        <xsl:text>GRAND: {format-number(sum(map:keys($subtotals)!$subtotals(.)),'#,##0.00')}&#xA;</xsl:text>
      </xsl:on-completion>
      <xsl:variable name="e" select="copy-of(.)"/>
      <xsl:variable name="ccy" select="string($e/wd:Annual_Salary/@wd:Currency)"/>
      <xsl:variable name="amt" select="xs:decimal($e/wd:Annual_Salary)"/>
      <xsl:next-iteration>
        <xsl:with-param name="subtotals"
          select="map:put($subtotals, $ccy,
                          (if (map:contains($subtotals,$ccy)) then $subtotals($ccy) else 0) + $amt)"/>
      </xsl:next-iteration>
    </xsl:iterate>
  </xsl:template>
</xsl:stylesheet>

USD: 281,000.00
GRAND: 353,000.00
i
Key idea: The map is the running state. map:put returns a new map (maps are immutable), threaded via xsl:next-iteration. map:keys($m)!$m(.) gives all values for the grand total.

Fault-tolerant total

xsl:try element form

Sum all annual salaries, but if any fails to cast to a number, count it as 0 instead of failing the run.

SOLUTION · XSLT 3.0 
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
  xmlns:xs="http://www.w3.org/2001/XMLSchema"
  xmlns:wd="urn:com.workday.report/INHCM0001-Outbound" expand-text="yes" exclude-result-prefixes="xs wd">
  <xsl:output method="text"/>
  <xsl:template match="/wd:Report_Data">
    <xsl:variable name="amounts" as="xs:decimal*">
      <xsl:for-each select="wd:Report_Entry">
        <xsl:try select="xs:decimal(wd:Annual_Salary)">
          <xsl:catch select="0"/>
        </xsl:try>
      </xsl:for-each>
    </xsl:variable>
    <xsl:text>Total payroll (bad values counted as 0): {format-number(sum($amounts),'#,##0.00')}&#xA;</xsl:text>
  </xsl:template>
</xsl:stylesheet>
OUTPUT · TEXT ✓ verified
Total payroll (bad values counted as 0): 353,000.00
i
Key idea: The element form of try/catch (portable to HE) wraps each cast. Building a typed sequence (xs:decimal*) and sum()-ing it beats threading a running total when you don't need streaming.
