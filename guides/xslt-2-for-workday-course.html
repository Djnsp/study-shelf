Phase 1 · 1.1

XML Basics

Workday integrations move XML. A Report-as-a-Service (RaaS) feed, a PECI extract, a Worker Sync — all arrive as a tree of nested tags. Four building blocks make up that tree:

  • Elements — the tags, e.g. wd:Report_Entry, wd:Name.
  • Attributes — name/value pairs on an element, e.g. wd:currency="USD".
  • Parent–child hierarchy — nesting. wd:Report_Entry is the parent of wd:Employee_ID.
  • Text nodes — the character data inside an element, e.g. the text Asha Rao inside wd:Name.
Example
Input XML
<wd:Report_Data xmlns:wd="urn:com.workday/bsvc">
  <wd:Report_Entry>
    <wd:Employee_ID>21001</wd:Employee_ID>
    <wd:Name>Asha Rao</wd:Name>
    <wd:Department>Engineering</wd:Department>
    <wd:Status>Active</wd:Status>
    <wd:Base_Pay wd:currency="USD">120000</wd:Base_Pay>
    <wd:Hire_Date>2021-03-15</wd:Hire_Date>
  </wd:Report_Entry>
  <wd:Report_Entry>
    <wd:Employee_ID>21002</wd:Employee_ID>
    <wd:Name>Mateo Diaz</wd:Name>
    <wd:Department>Finance</wd:Department>
    <wd:Status>Active</wd:Status>
    <wd:Base_Pay wd:currency="USD">96000</wd:Base_Pay>
    <wd:Hire_Date>2019-11-04</wd:Hire_Date>
  </wd:Report_Entry>
  <wd:Report_Entry>
    <wd:Employee_ID>21003</wd:Employee_ID>
    <wd:Name>Priya Nair</wd:Name>
    <wd:Department>Engineering</wd:Department>
    <wd:Status>Terminated</wd:Status>
    <wd:Base_Pay wd:currency="USD">142000</wd:Base_Pay>
    <wd:Hire_Date>2018-06-20</wd:Hire_Date>
  </wd:Report_Entry>
</wd:Report_Data>

This is the shared sample we transform throughout the course. Here wd:Base_Pay is an element whose text node is 120000 and which carries the attribute wd:currency="USD". Its parent is wd:Report_Entry; its siblings include wd:Name and wd:Status.

Phase 1 · 1.2

Namespace Awareness

Every Workday element lives in a namespace — a URI bound to a prefix. The sample binds xmlns:wd="urn:com.workday/bsvc". To match those elements in your stylesheet you must declare the same URI. The prefix name is yours to choose; what must match is the URI it points to.

Forgetting this is the No. 1 reason a template “matches nothing.” match="Report_Entry" (no prefix) will never hit wd:Report_Entry, because an unprefixed name means no namespace. Use exclude-result-prefixes to keep helper prefixes out of your output.

Example
Input XML
<wd:Report_Data xmlns:wd="urn:com.workday/bsvc">
  <wd:Report_Entry>
    <wd:Employee_ID>21001</wd:Employee_ID>
    <wd:Name>Asha Rao</wd:Name>
    <wd:Department>Engineering</wd:Department>
    <wd:Status>Active</wd:Status>
    <wd:Base_Pay wd:currency="USD">120000</wd:Base_Pay>
    <wd:Hire_Date>2021-03-15</wd:Hire_Date>
  </wd:Report_Entry>
</wd:Report_Data>
XSLT
<xsl:stylesheet version="2.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:wd="urn:com.workday/bsvc"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    exclude-result-prefixes="wd xs">

  <xsl:template match="wd:Report_Entry">
    <!-- fires because the wd: URI matches the input -->
    <worker><xsl:value-of select="wd:Name"/></worker>
  </xsl:template>

</xsl:stylesheet>
Output
<worker>Asha Rao</worker>

Phase 5 · 5.4

Performance Tuning

On large extracts, the descendant axis // rescans the whole subtree every time. Anchor paths, and replace repeated lookups with keys (xsl:key → key()), which turn an O(n²) nested scan into a near-O(1) indexed lookup.

    <wd:Manager_ID>21003</wd:Manager_ID>
  </wd:Report_Entry>
  <wd:Report_Entry>
    <wd:Employee_ID>21003</wd:Employee_ID>
    <wd:Name>Priya Nair</wd:Name>
    <wd:Manager_ID/>
  </wd:Report_Entry>
</wd:Report_Data>
XSLT
<xsl:key name="byId" match="wd:Report_Entry" use="wd:Employee_ID"/>

<!-- O(1) lookup instead of //wd:Report_Entry[wd:Employee_ID=$id] -->
<xsl:variable name="match" select="key('byId', '21003')"/>
<Name><xsl:value-of select="$match/wd:Name"/></Name>
Output
<Name>Priya Nair</Name>
