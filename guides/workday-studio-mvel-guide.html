01

What MVEL is, and why Studio uses it

MVEL (the MVFLEX Expression Language) is a small, dynamically typed expression language that runs inside the Workday Studio assembly framework. Wherever an integration needs a little bit of inline logic — set a property, test a condition, build a filename, reshape a message — you write it as an MVEL expression rather than a full Java class or XSLT stylesheet.

Think of MVEL as the glue language of an assembly. XSLT transforms documents, Java custom steps do heavy lifting, and MVEL handles the thousands of tiny decisions in between: "is this the last record in the batch?", "what is the company name from the integration attribute?", "route XML one way and everything else another."

Runtime version
The Workday Runtime supports MVEL version 1.3, which is also compatible with MVEL 1.2. This matters: newer MVEL features documented on the public web may not behave identically in Studio. When in doubt, prefer the idioms shown in this guide — they are drawn from production integrations running on the Workday runtime.

What makes Studio's MVEL distinctive

Standard MVEL evaluates expressions against a context of variables. Studio supplies that context automatically through a set of implicit variables — context, props, vars, parts, message, util, intsys, lp, and more. These are the bridge between the language and the mediation pipeline. Master those variables and you have mastered most of what MVEL-in-Studio actually requires.

Two facts shape everything else:

  • MVEL reads and writes the MediationContext. Every expression runs against the message currently flowing through the assembly — its parts, its headers, and the properties and variables attached to it.
  • MVEL auto-converts between types. A string can become a message part; a part can become a variable; a list literal can carry both content and MIME type. This is what lets one short line do real work.
02

Where you write MVEL in Studio

MVEL is not confined to one place. It appears in several assembly components, and the Assembly Editor signals which property fields accept it. Knowing the host tells you what the expression is expected to return.

The eval step — run expressions directly

The eval step is the workhorse. Its default (and only) language is MVEL. It holds one or more expression elements, evaluated in the order written — so a later expression can use a property set by an earlier one.

<cc:eval>
    <cc:expression>props['XX'] = 'Fergal'</cc:expression>
    <cc:expression>props['YY'] = 'Hello ' + props['XX']</cc:expression>
</cc:eval>

After this step, props['YY'] holds 'Hello Fergal'. The ordering guarantee is the single most useful property of the eval step — you can build state up line by line.

Property fields — three flavours

In the Properties view, an icon before a property name tells you what kind of MVEL it accepts:

template

A literal string with embedded expressions in @{ } notation. Used by write text, log messages, filenames, URIs.

text @{mvel.exp} some text
expression

A bare MVEL expression. Strings must use single quotes.

'text' + mvel.exp + 'more text'
numeric

An expression that must evaluate to a number.

props['retryCount'] + 1

Templates in write and log steps

Inside a write step or log message, anything in @{ } is evaluated and spliced into the surrounding text. This is how dynamic XML, filenames, and log lines get built:

<wd:header>STARTS : total workers = @{props['is.paged.get.total.results']}</wd:header>
props['LOGfilename'] = 'ErrorLog_' # props['CompanyName'] # '_' # props['File_date_final'] # '.txt'

Routing — the mvel-strategy

A route can choose a sub-route using an MVEL Boolean. The first choose-route whose expression is true wins. (Covered in detail in section 16.)

<cc:mvel-strategy>
    <cc:choose-route expression="parts.length == 1" route="singlePartRoute"/>
    <cc:choose-route expression="parts.length > 1"  route="multiPartRoute"/>
</cc:mvel-strategy>

Validation — validate-exp

A validate-exp step asserts that an MVEL Boolean is true, failing the message otherwise. Used heavily for unit-testing assemblies and guarding preconditions:

<cc:validate-exp>
    <cc:expression>xmldiff.isDifferent() == true</cc:expression>
</cc:validate-exp>
The mctx: protocol
In expressions you may also see the mctx: URL specifier to reach context variables, e.g. mctx:vars/fred accesses the variable fred. In day-to-day work the vars['fred'] form is far more common.
03

The implicit variables

Every MVEL expression in Studio runs with these variables already in scope. This is the most important table in the guide — it is the entire surface area between the language and the pipeline. Each entry below is followed by its real signature patterns.

context

The MediationContext — the master object carrying the message, variables, properties, error flags, audit, customer id and dynamic endpoint around the assembly. Almost everything is reachable from here; the other variables are convenience views onto it.

context.getProperty('myProperty')
context.containsProperty('inToken')
context.removeProperty('localURI')
context.getErrorMessage()
context.getCustomerId()
props

Shorthand adapter over message properties (PropertyMapAdapter). The single most-used variable. Read and write with bracket or dot notation. Properties are the scratchpad of an assembly.

props['myProperty']           // bracket form (always safe)
props.myProperty              // dot form (no dots in the name!)
props['bean.property']        // value set by a custom Spring bean
props['DoNotProcess'] = false
vars

The MediationContext variables as a Map (MessageContextVariables). Variables hold richer payloads than properties — each carries content, a MIME type, and is XPath-addressable.

vars['myVariable'].text
vars['myVariable'] != null          // is it defined?
vars['myVariable'].mimeType
vars['myVariable'].xpath('/a/b')
vars.setVariable('out', parts[0].source, parts[0].mimeType)
parts

Array access to the message parts via MessageAdapter. parts[0] is the root part, parts[1] the first attachment, and so on. The primary way to read and reshape the live message.

parts[0].text                       // root part content
parts[1].text                       // first attachment
parts[0].getHeader('someHeader')
parts[0].mimeType
parts[0].getAs(String)
parts[0].xpath('/a/b')
parts[0].xpathB('/a/b')             // boolean: does the node exist?
parts[0].xpathF('/a/b')             // returns XML fragment
parts.length
message

The MediationMessage interface — the whole message rather than a single part. Useful for setting the root part, adding attachments, or grabbing everything as text.

message.rootPartAsText
message.getMimeType()
message.setRootPart(parts[0].source)
message.addAttachment(...)
message.isNullContentRootPart()
util

MVELUtilHelper — 40+ convenience functions for dates, times, collections, string cleanup and batch testing. Your standard library inside an expression.

util.isLastMessageInBatch()
util.currentDateAsString()
util.currentDateTimeAsString('PST')
util.cleanString(props['summary'])
util.HashMap()                      // a fresh java.util.HashMap
util.listToCommaDelimString(myList)
intsys

The integration system configuration: attributes, maps and reference data defined on the Integration System. Populated by the workday-in transport / GetIntegrationSystems sub-assembly.

intsys.getAttribute('Company Name')
intsys.getAttributeAsBoolean('SENDNOT')
intsys.getAttributeReferenceDataList('Paygroups', 'WID')
intsys.integrationMapLookup('mapName', 'key')
lp

Launch parameters passed to the integration event. Read prompt values, references, WIDs and descriptors the run was launched with. Requires the launch-parameter XML to be assigned first.

lp.isSet()
lp.getSimpleData('Parameter Label')
lp.getReferenceData('PICOF Input Document', 'Document_ID')
lp.getWIDs('PICOF Input Document')
lp.getDescriptor('PICOF Input Document', wid)
lp.getIntegrationEventWID()
da

Document Accessor — reach documents attached to the integration event and pull them into variables for processing.

da.size()
da.toVar('eib_transform_output.txt', 'var1')
env

JVM system properties (those set with -D on the command line).

env['cc.hostname']
spring

The Spring ApplicationContext for the WSAR — fetch beans and their properties.

spring.getBean('myBean')
spring.getBean('fred').name
mtable

MTableAdapter — read and write an in-memory table of data by row index and column name.

mtable['my_property'].get(0, 'Data_Column')
mtable['my_property'].set(0, 'Data_Column', 'my_test_data')
xmldiff

Result of an xmldiff step (XMLDiffStepResult). Inspect whether two documents differ and drill into named definition results.

xmldiff.isSet() == true
xmldiff.isDifferent() == true
xmldiff.getDefinitionResults().get("firstNameDiff").isDifferent()
ftp

Result of an FTP list operation (MVELFTPHelper). Test URI schemes and SSL modes.

ftp.isSftp('sftp://server/dir')
ftp.isExplicitSSL('ftpse:/server/dir')
epg

External pay groups (Get_External_Paygroups result). Internal / Cloud-developer use for payroll period date math.

epg.isSet()
epg.getStartDate('periodWid')
epg.getCurrentPeriod('payGroupWid', 'date')
1,000,000-character limit on XPath methods
xpath, xpathB, and xpathF are processed entirely in memory. On messages larger than ~1M characters they throw "Output greater than limit of 1,000,000". For large payloads use streaming APIs such as the write step's xml-stream element instead.
04

Core language syntax

MVEL's grammar is deliberately small. If you know any C-family language most of this is muscle memory — the few Studio-specific wrinkles are called out.

Literals

props['s'] = 'a single-quoted string'      // strings use SINGLE quotes in expression fields
props['n'] = 28                              // integer
props['d'] = 3.14                            // decimal
props['b'] = true                            // boolean
props['x'] = null                            // null
props['list'] = ['a', 'b', 'c']              // inline list (also used for content+mime, see s.8)

Operators

CategoryOperatorsNotes
Arithmetic+ - * / %+ also concatenates strings.
String concat+  and  #Studio integrations use both; see below.
Comparison== != < > <= >=== compares values, not references, for strings.
Logical&& ||  or the words  and orBoth spellings work.
Ternarycond ? a : bThe conditional workhorse — see section 14.
Regex match~=Left matches the right-hand regex.
Emptinessempty keywordTrue for null, empty string, empty collection.

String concatenation: + versus #

You will see two concatenation styles in real assemblies. Both join strings; pick one and be consistent within an expression.

props['greeting'] = 'Hello ' + props['name']                 // the + operator
props['fname']    = 'HTML_' # props['CompanyName'] # '.HTML'   // the # operator

The # form is common in Workday-authored integrations for assembling filenames and formatted timestamps from substrings, because it reads cleanly when chaining many fragments:

props['Startdatetime_final'] =
      props['current.datetime'].substring(5,7)  # props['current.datetime'].substring(8,10)
    # props['current.datetime'].substring(0,4)  # ' '
    # props['current.datetime'].substring(11,13) # ':'
    # props['current.datetime'].substring(14,16) # ':'
    # props['current.datetime'].substring(17,19)

Equality, emptiness and null

These three comparisons cover the vast majority of conditions you will write:

props['Severity'] == empty                    // null OR empty string OR empty collection
props['inToken']  != null                     // strictly: has a (possibly empty) value
props['count']    == 0                         // numeric compare
props['flag']     == true                      // boolean compare
props['mime']     ~= 'text/xml.*'              // regex: does it start with text/xml?
empty vs null — prefer empty
empty is the safer default in Studio. props['x'] == empty is true whether the property is unset, an empty string, or an empty list — which is usually what you mean when you ask "did I get a value?". Reserve != null for the narrow case where an empty string should count as present.

Method chaining and Java strings

Property and variable values are real Java objects, so their methods are available directly:

props['code'] = props['ref'].substring(props['sep'] + 1)
props['lower'] = props['inType'].trim().toLowerCase()
props['hasDot'] = props['filename'].indexOf('.') != -1
props['clean'] = props['raw'].replace('</Record>', '')
05

Working with properties (props)

Properties are the assembly's scratchpad — named slots that live on the MediationContext for the life of the message. They are how one step passes a value to the next. props is the adapter you use to read and write them.

Read and write

props['CompanyName'] = intsys.getAttribute('Company Name')   // write
props['greeting'] = 'Hello ' + props['CompanyName']           // read + write
props.DoNotProcess = false                                    // dot form

Existence and removal

Guard before you read, and clean up when done — both are extremely common in production:

context.containsProperty('inToken')        // true if the property exists
props.containsKey('inToken')               // equivalent
context.removeProperty('localURI')         // delete one property

Removing a batch of working properties at the end of a sub-assembly keeps the context tidy:

foreach (name : {'inMessages', 'inIsClearMessages', 'inMinLogLevel'}) {
    context.removeProperty(name)
}
Gotcha: dots in property names

MVEL 1.3 mis-parses a property whose name contains a dot when you assign with bracket notation. This fails with org.mvel.CompileException: unterminated '[':

props['SplitInitialPage.last.in.batch'] = props['mediation.splitter.last.in.batch']

The reliable workaround is to assign through context.setProperty:

context.setProperty('SplitInitialPage.last.in.batch', props['mediation.splitter.last.in.batch'])

Reading a dotted-name property with brackets is fine; it is the bracket assignment that trips. Many teams simply avoid dots in property names entirely.

06

Working with variables (vars)

Variables are heavier than properties. Where a property holds a simple value, a variable holds a message-like payload — content plus a MIME type, and it is XPath-addressable. Use a variable when you need to stash a whole document, an attachment, or an XML fragment for later.

Define, test, read

vars['fred'] = '<hello>world</hello>'      // create with default mime text/xml
vars['fred'] != null                          // is it defined?
vars['fred'].text                             // its content as text
vars['fred'].mimeType                         // its MIME type
vars['fred'].xpath('/hello')                  // XPath straight into the variable

setVariable / isVariable

The setVariable method gives you explicit control of content and MIME type in one call, and isVariable is the safe existence check. This pair shows up constantly in reusable sub-assemblies:

vars.setVariable(props['inReturnResults'], parts[0].source, parts[0].mimeType)

varname = props['inBuildRequestDataLocationId'];
props['localIsValueDefined'] = vars.isVariable(varname) && (vars[varname] != null);
Property or variable?
Reach for a property for flags, counts, names, small strings. Reach for a variable when the thing has structure you will query with XPath, or when it is large enough that you want it carried as a typed payload rather than a string.
07

Working with message parts (parts[])

parts is array-based access to the live message. The indexing rule is fixed and worth memorising: parts[0] is the root part, parts[1] is the first attachment, parts[2] the second, and so on.

Reading

parts[0].text                               // content of the root part
parts[1].text                               // content of the first attachment
parts[0].mimeType                           // MIME type of the root part
parts[0].getHeader('Content-Length')        // a header value
parts[0].getAs(String)                      // root part as a String
parts[0].getAs(DOMSource)                   // root part as a DOMSource
parts.length                                // how many parts

Writing

parts[0].setText('Here is some new content')
parts[0].setMimeType('text/xml')
parts[0].setAs('Here is some new content')
parts[0].setHeader('SomeHeader', 'SomeValue')

Testing content

parts[0].isXml()                            // is the root part XML?
parts[1].text != null                       // attachment present and has text
parts[0].getHeader('someHeader') == 'someValue'
parts[0].mimeType ~= 'text/xml.*'           // regex match on the MIME type
.source vs .text
You will see both parts[0].text and parts[0].source. Use .text when you want the content as a string to inspect or concatenate; use .source when handing the part on to setVariable or another component that wants the underlying source object preserved.
08

Auto-conversion syntax

This is MVEL-in-Studio's most powerful idea, and the one that most surprises newcomers. Assigning to a vars[...], parts[...], or context.message slot auto-converts the right-hand side into the right kind of object — and the inline-list literal [ content, mimeType ] lets you supply both content and MIME type at once.

Variables

vars['fred'] = '<hello>world</hello>'           // content + default mime text/xml
vars['fred'] = [ 'Hello World', 'text/plain' ]     // content + explicit mime
vars['fred'] = [ '<hello>world</hello>' ]         // content only, mime defaults to text/xml
vars['fred'] = [ 23 + 5, 'text/plain' ]            // content can be any expression -> "28"
vars['fred'] = parts[1]                            // copy from the first attachment
vars['fred'] = message                             // copy the whole (multi-part) message
vars['fred'] = parts[0].xpathF('/dink/donk')       // an XPath fragment
vars['fred'] = null                                // REMOVE the variable

Message parts

parts[0] = '<hello>world</hello>'              // assign content to the root part
parts[1] = [ 'Hello World', 'text/plain' ]         // create/replace the first attachment
parts[0] = [ 23 + 5, 'text/plain' ]                // content from an expression
parts[0] = vars['fred']                            // copy a variable into a part
parts[2] = parts[1]                                // copy first attachment to second
parts[0] = null                                    // remove root part (see note)
Edge rules worth knowing
  • You cannot create non-sequential attachments — you can't assign parts[9] if parts[8] doesn't exist.
  • parts[0] = null removes the root part: if attachments exist, the first attachment is promoted to root; if not, the root becomes an empty text/xml part (a message must always have a root).

Whole messages

To replace the entire message, assign to context.message:

context.message = '<hello>world</hello>'          // new single-part message, text/xml
context.message = [ 'Hello World', 'text/plain' ]  // with explicit mime
context.message = vars['fred']                     // from a variable's content + mime
context.message = parts[0]                          // collapse to just the root part
09

XPath inside MVEL

MVEL and XPath work hand in hand: XPath navigates the XML, MVEL decides what to do with the result. Three methods cover every case, available on parts[...] and vars[...] alike.

MethodReturnsUse it to…
xpath('/a/b')stringget the text value of a node.
xpathB('/a/b')booleantest whether a node exists / a condition holds.
xpathF('/a/b')XML fragment (string)pull a node-set out as XML; empty string if no match.

Counting — the most common real-world use

XPath's count() function combined with a routing decision is the backbone of "did we get any records, and if so process them" logic:

props['Job_record_count']        = parts[0].xpath('count(/Root/Record/Job_Record)')
props['Personal_record_count']   = parts[0].xpath('count(/Root/Record/Personal_record)')
props['Employment_record_count'] = parts[0].xpath('count(/Root/Record/Employment_record)')
props['Total_record_count'] =
      props['Job_record_count'] + props['Personal_record_count'] + props['Employment_record_count']

…then route on the total (see section 16):

<cc:choose-route expression="props['Total_record_count'] > 0" route="ProcessRoute"/>
<cc:choose-route expression="props['Total_record_count'] == '0'" route="EmptyFileRoute"/>

Namespaces

By default the Workday runtime takes all prefix-to-namespace mappings from your assembly.xml. Supply a namespace inline only to override that default:

parts[0].xpath('/a/b')                                       // uses assembly.xml prefixes
parts[0].xpath('/xx:a/xx:b', 'xx http://www.somewhere.com')  // override for prefix xx
parts[0].xpath('/pi:PayGroup/pi:Header/pi:Pay_Group_Name')   // real PECI example
Remember the 1M-character limit
xpath, xpathB, and xpathF run in memory. For multi-megabyte payloads, switch to the write step's xml-stream element rather than XPath-ing the whole document.

The util helper (MVELUtilHelper)

util is your standard library inside an expression — over 40 functions for dates, collections, strings and batch state. Below are the ones that actually appear in production integrations, grouped by job.

Dates & times

util.currentDateAsString()                  // today as a string
util.currentDateTimeAsString('PST')         // now, in a named timezone
util.currentTime()                          // current time
util.Date()                                 // a java.util.Date you can format/compare
util.compareDates(dateA, dateB)             // ordering of two dates

Collections

util hands you fresh Java collections you can build up across expressions:

props['map']  = util.HashMap();             // == new java.util.HashMap()
props['list'] = util.ArrayList();           // == new java.util.ArrayList()
props['set']  = util.HashSet();
props['iter'] = util.ObjectIterator(someCollection);

props['map'].put('key', 'value');
props['list'].add('item');

String & list utilities

util.cleanString(props['summary'])          // strip chars that would break XML
util.listToCommaDelimString(myList)         // ['a','b','c'] -> "a,b,c"
util.listToDelimString(myList, '|')         // custom delimiter
util.setCurrentFilename(props._attachment_filename)

Batch state

When a splitter fans a batch out into many messages, isLastMessageInBatch tells you when you are processing the final one — the standard hook for "write the footer / close the file" logic:

props['LastbatchSequence'] = util.isLastMessageInBatch()
props['is.last.record']    = util.isLastMessageInBatch()
Deprecated: getLatestWWSVersion()
Avoid util.getLatestWWSVersion() (and util.latestWWSVersion). Workday strongly recommends explicit, versioned Web service requests for stability and backward compatibility. Pin the WWS version in your requests instead.
11

Integration system access (intsys)

An integration's behaviour is usually driven by integration attributes and maps configured on the Integration System in the tenant — company name, file type, recipient email, feature flags. intsys reads them at runtime so the same assembly can serve many configurations.

Attributes

props['CompanyName']      = intsys.getAttribute('Company Name')
props['FileType']         = intsys.getAttribute('File Type')
props['MAILTo']           = intsys.getAttribute('Mail_to')
props['SourceSystemName'] = intsys.getAttribute('Source System Name')

Typed and reference-data attributes

props['SENDNOT']   = intsys.getAttributeAsBoolean('SENDNOT')        // a boolean flag
props['LOGENABLE'] = intsys.getAttributeAsBoolean('LOG enable')
props['PGID']      = intsys.getAttributeReferenceDataList('Paygroups', 'WID')  // a list of WIDs
props['one']       = intsys.getAttributeReferenceData('SomeAttr')

Map lookups

Integration maps translate a Workday value to an external one (and back):

props['ext'] = intsys.integrationMapLookup('CountryMap', props['wdCountry'])
props['wd']  = intsys.integrationMapReverseLookup('CountryMap', props['extCountry'])
A tidy pattern
Teams often dedicate a single early eval step to copying every needed integration attribute into a property — one place that documents "everything this integration is configured by." The rest of the assembly then reads plain properties.
intsys needs a service defined
Using intsys to read an attribute at runtime fails unless the workday-in transport has a service defined that declares the integration's attributes and maps. The transport calls Get_Integration_Systems transparently to populate intsys; with no service, convenience methods like intsys.name have nothing to read.
12

Launch parameters (lp)

When an integration event runs, it is launched with parameters — the prompt values, document references and instance sets the user (or scheduler) supplied. lp reads them. The label argument matches either the parameter's name or its label.

Guard first

lp.isSet()             // true if the launch-parameter XML is present and well-formed

Simple and reference values

lp.getSimpleData('Effective Date')                       // string/date/number parameters
lp.exists('Effective Date')                              // does the parameter exist?
lp.getDate('Effective Date')                             // xsd:date as a string (time stripped)
lp.getReferenceData('PICOF Input Document', 'Document_ID')

Multi-value (instance set) parameters

lp.getWIDs('PICOF Input Document')                       // list of WIDs
lp.getMap('Some Prompt')                                 // map keyed by instance, with all props
lp.getDescriptor('PICOF Input Document', wid)            // the descriptor for one WID

Event metadata

lp.getIntegrationEventWID()
lp.getIntegrationSystemRefWID()
lp.getUserName()
lp.getSentOn()

Worked example: resolve a launched document

A canonical PICOF pattern — take the launched input document, split its collection/entry reference, and pull out the filename:

props['input.document.wids']      = lp.getWIDs('PICOF Input Document')
props['input.document.wid']       = props['input.document.wids'].get(0)
props['input.document.reference'] = lp.getReferenceData('PICOF Input Document', 'Document_ID')
props['input.document.filename']  = lp.getDescriptor('PICOF Input Document', props['input.document.wid'])

props['index.of.separator']       = props['input.document.reference'].indexOf('/')
props['input.document.collection'] = props['input.document.reference'].substring(0, props['index.of.separator'])
props['input.document.entry']      = props['input.document.reference'].substring(props['index.of.separator'] + 1)
Assign the XML before using lp
Before reading with lp, the launch-parameter XML (wd:Launch_Integration_Event_Data) must be assigned to the variable wd.launchparameters. The workday-in transport normally does this for you; for externally launched integrations you may construct and assign it yourself.
13

The Document Accessor (da)

da reaches the documents attached to the integration event — for example the output of a prior EIB transform — and pulls them into a variable you can then process.

da.size()                                       // how many documents are available
da.toVar('eib_transform_output.txt', 'var1')    // load that document into variable var1

After da.toVar(...) the content is an ordinary variable, so everything in section 6 applies:

da.toVar('eib_transform_output.txt', 'var1');
props['rowCount'] = vars['var1'].xpath('count(/Root/Row)');
da vs lp for documents
Use lp when you need the reference to a launched document (its WID, collection, filename). Use da when you need the document's content pulled into the assembly for transformation.
14

Control flow & Java interop

A single expression can hold multiple statements separated by ;, full if/else blocks, foreach loops, and direct calls into Java. This is where MVEL stops being a calculator and becomes a tiny programming language.

Ternary — the conditional you will reach for most

props['c2p.pMethod'] = props['isPerformPost'] == true ? 'POST' : 'PATCH'
props['p.fullfile']  = parts[0].xpath('ws:Worker_Sync/ws:Header/ws:Full_File') == true ? 'Y' : 'N'
props['outErrorMessage'] = (context.getErrorMessage() != empty)
                           ? context.getErrorMessage()
                           : context.exception.message

Ternaries also nest, and the "do nothing" branch is just an empty string — a common way to conditionally append:

props['Prop.Last.Name'] == empty ? props['p.warning.log'].append('LastName, ') : ''
props['Output.Filename'] = props['prefix'] +
    ((props['index.of.dot'] == -1) ? props['filename'] : props['filename'].substring(0, props['index.of.dot']))

if / else

if (props['inStaticCodeAnalysisExemptionList'] == empty) {
    props['inStaticCodeAnalysisExemptionList'] = new java.util.ArrayList();
}

if (props['xlogger_main'] == null) {
    props['xlogger_main'] = new com.workday.jds.excellogger.ExcelLoggerImpl();
} else {
    props['xlogger_main'].reset();
}

// iterate a literal set of names
foreach (name : {'inMessages', 'inIsClearMessages', 'inMinLogLevel'}) {
    context.removeProperty(name);
}

// iterate a map's keys
foreach (key : props['localSubAssemblyDetailMap'].keySet()) {
    if (org.apache.commons.lang3.StringUtils.contains(
            props['localSubAssemblyDetailMap'].get(key), 'CORE COMPONENTS')) {

}

Because values are Java objects you can test their type and instantiate any class on the classpath:

props['Error.File']   = new java.lang.StringBuffer();

StringBuffer for accumulating logs
When you build an error or warning report row by row across many split messages, allocate a java.lang.StringBuffer once into a property and .append(...) to it. It is far cheaper than repeated string concatenation and is the standard Workday logging idiom.

Error handling in expressions

Inside error handlers and guard logic, context exposes the current exception and the flags that control whether processing continues. These let an assembly catch a failure, record it, and decide its fate.

Reading the error

context.getErrorMessage()                   // the framework's error message, if any
context.exception.message                   // the underlying exception's message
context.isAbort()                           // has the message been marked to abort?

The two-source pattern — prefer the friendly error message, fall back to the raw exception:

props['outErrorMessage'] = (context.getErrorMessage() != empty)
                           ? context.getErrorMessage()
                           : context.exception.message

Controlling the outcome

context.setException(someThrowable)         // raise/replace the exception
context.setErrorHandled(true)               // mark handled; stop further error handlers firing
context.setAbort(true)                      // abort processing of this message
setErrorHandled stops the chain
When an exception is raised, error handlers fire in turn. Calling context.setErrorHandled(true) signals that you have dealt with it, so no further handlers run — useful when one handler should fully own a particular failure.

Routing with mvel-strategy

The route component can pick a sub-route using MVEL. Inside an mvel-strategy, each choose-route pairs a Boolean expression with a sub-route name. The first expression that evaluates true wins. If none match, an error is thrown — unless you set filter="true" to suppress it.

The canonical shape

<cc:mvel-strategy>
    <cc:choose-route expression="parts.length == 1" route="singlePartRoute"/>
    <cc:choose-route expression="parts.length > 1"  route="multiPartRoute"/>
</cc:mvel-strategy>

Real routing conditions from production

<!-- process only when there are records -->
<cc:choose-route expression="props['Total_record_count'] > 0" route="Process"/>
<cc:choose-route expression="props['Total_record_count'] == '0'" route="EmptyFile"/>

<!-- guard against empty or null counts -->
<cc:choose-route expression="props['Paygroup.EMP.COUNT'] != empty and props['Paygroup.EMP.COUNT'] > 0" route="HaveEmployees"/>
<cc:choose-route expression="props['Paygroup.EMP.COUNT'] == 0 or props['Paygroup.EMP.COUNT'] == empty" route="NoEmployees"/>

<!-- branch on a normalised attribute value -->
<cc:choose-route expression="props['inTargetType'] == 'variable'" route="ToVariable"/>
<cc:choose-route expression="props['inTargetType'] == 'message'"  route="ToMessage"/>

<!-- XML vs non-XML -->
<cc:choose-route expression="parts[0].isXml()" route="XmlRoute"/>
<cc:choose-route expression="true"             route="DefaultRoute"/>
A trailing expression="true" is your default branch
Because the first match wins, a final choose-route expression="true" acts as an else/catch-all — cleaner than relying on the no-match error. You will see it everywhere.

Sibling strategies follow the same first-match shape: xpath-strategy (route on an XPath result, XML only), regex-strategy (route on a regular expression, text only), plus round-robin-strategy and loop-strategy for distribution and iteration.

Worked examples

Four end-to-end snippets drawn from real integrations, annotated so each line earns its place. Read these once you are comfortable with the variables — they show how the pieces combine.

1 — Build a timestamped output filename

Read configuration from intsys, format "now" into pieces, and assemble a filename with the # operator.

// 1. pull config and a timestamp
props['CompanyName']    = intsys.getAttribute('Company Name');
props['current.datetime'] = util.currentDateTimeAsString('PST');

// 2. carve the date string into MMDDYYYYHHMM
props['File_date_final'] =
      props['current.datetime'].substring(5,7)   # props['current.datetime'].substring(8,10)
    # props['current.datetime'].substring(0,4)   # props['current.datetime'].substring(11,13)
    # props['current.datetime'].substring(14,16);

// 3. compose the final names
props['LOGfilename']  = 'ErrorLog_' # props['CompanyName'] # '_' # props['File_date_final'] # '.txt';
props['LOGHTMLFILE']  = 'HTML_'     # props['CompanyName'] # '_' # props['File_date_final'] # '.HTML';

2 — Count records, then route

The "is there anything to process?" gate. Counting in an eval step, routing in the strategy.

// eval step
props['Job_record_count']        = parts[0].xpath('count(/Root/Record/Job_Record)');
props['Personal_record_count']   = parts[0].xpath('count(/Root/Record/Personal_record)');
props['Employment_record_count'] = parts[0].xpath('count(/Root/Record/Employment_record)');
props['Total_record_count'] =
    props['Job_record_count'] + props['Personal_record_count'] + props['Employment_record_count'];
<!-- route -->
<cc:mvel-strategy>
    <cc:choose-route expression="props['Total_record_count'] > 0"  route="GenerateOutput"/>
    <cc:choose-route expression="props['Total_record_count'] == '0'" route="EmptyFileNotice"/>
</cc:mvel-strategy>

3 — Resolve a launched PICOF document

From a launch parameter to a usable collection/entry/filename triple.

props['input.document.wids']       = lp.getWIDs('PICOF Input Document');
props['input.document.wid']        = props['input.document.wids'].get(0);
props['input.document.reference']  = lp.getReferenceData('PICOF Input Document', 'Document_ID');
props['input.document.filename']   = lp.getDescriptor('PICOF Input Document', props['input.document.wid']);

props['index.of.separator']        = props['input.document.reference'].indexOf('/');
props['input.document.collection'] = props['input.document.reference'].substring(0, props['index.of.separator']);
props['input.document.entry']      = props['input.document.reference'].substring(props['index.of.separator'] + 1);

4 — Accumulate a validation warning report

Allocate a buffer once, append conditionally per field, and merge into a master warning file.

// once, up front
props['Warning.File'] = new java.lang.StringBuffer();

// per record, conditionally append missing-field warnings
props['Prop.Last.Name'] == empty ? props['p.warning.log'].append('LastName, ') : '';
props['Prop.DOB']       == empty ? props['p.warning.log'].append('DOB, ')      : '';

// merge a sub-report only if it has content
if (props['RescindValidationWarn.File'].toString() != empty) {
    props['Warning.File'].append(props['RescindValidationWarn.File']);
}

Gotchas & best practices

Watch out
  • Dots in property names break bracket assignment in MVEL 1.3. Assign such names with context.setProperty('a.b.c', value) or avoid dotted names.
  • XPath has a 1M-character ceiling. xpath/xpathB/xpathF run in memory; large payloads need streaming (xml-stream).
  • Double-quoted strings in expression fields. In an expression-type property, strings should use single quotes; use double quotes only inside templates or where the field expects them.
  • Non-sequential attachments. You can't assign parts[9] unless parts[8] exists.
  • getLatestWWSVersion() is deprecated. Pin explicit WWS versions.
  • intsys with no service defined fails at runtime — define the attribute/map service on the workday-in transport.
Do this instead
  • Prefer empty over != null for "did I get a value?" checks.
  • Always bracket-access properties and variables (props['x']); reserve dot form for names you control and know are dot-free.
  • One config eval step. Copy all intsys attributes into properties up front so the rest of the assembly reads plain properties.
  • End with expression="true" as the catch-all route.
  • Clean up working properties with a foreach + context.removeProperty at sub-assembly boundaries.
  • StringBuffer for reports; util.cleanString(...) before writing text into XML.
  • Lean on eval ordering — build state line by line; a later expression sees an earlier one's result.
